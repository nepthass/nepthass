# v1.0.0 Discord-only release readiness

Status: **candidate preparation; not approved for release**. This document records the local audit on 2026-10-31. It does not authorize a commit, push, tag, deployment or release.

## 1. Product boundary and feature inventory

NeptHass v1.0.0 is a stable commitment to the existing self-hosted Discord/Home Assistant bridge. It has no browser product, listening HTTP server or second user interface.

Included:

- Discord connection, slash commands and interactive `/setup`.
- Home Assistant entity discovery and `/sync`.
- Explicit deny-by-default sharing with read/control permissions and aliases.
- Status and control through Discord; control remains limited to lights and switches.
- Home Assistant REST and WebSocket clients, reconnection and reconciliation.
- Sensor monitoring with conservative registry-owned semantics.
- Notification channel, rules, durations, hysteresis, unit binding, start-up alert handling and monitoring-down notices.
- SQLite persistence, migrations and audit logging.
- Docker and Docker Compose deployment.

Not included:

- Dynamic/generic sensor configuration, hazard-class expansion, quiet hours or a persisted notification outbox.
- Multi-guild operation, multiple application instances or horizontal scaling.
- A published container image; the current distribution is source plus Dockerfile.

## 2. Supported environment

| Component | Supported baseline |
| --- | --- |
| Deployment host | Linux with Docker Engine and Compose |
| Container runtime user | non-root UID/GID 65532 |
| Container base | `gcr.io/distroless/static-debian12:nonroot` |
| Source build | Go 1.27 |
| Home Assistant | reachable REST API and `/api/websocket`; long-lived token |
| Discord | one guild; bot application with slash-command registration |
| Persistence | SQLite database on the `/data` volume |

Windows and macOS may host Docker Desktop, but native non-container execution is not the documented production path. Architectures supported by the upstream Go and distroless images are expected to work but have not all been release-tested.

## 4. Installation and upgrade

Fresh installation follows the [setup guide](../setup.md): create the Discord application, create a Home Assistant token, fill `.env`, run `docker compose up -d --build`, then use `/setup` in Discord.

Upgrade procedure:

1. Stop NeptHass without removing its named data volume.
2. Back up the `/data` volume and `.env`.
3. Pull the desired source revision and rebuild the image.
4. Start NeptHass and inspect logs and `/health`.
5. Verify `/notifications status`, `/notifications list`, `/devices` and one authorized status/control flow.

The v1.0.0 candidate adds no migration beyond the four already released migrations. A v0.5.0 database opens without schema changes. Older databases migrate in order; a binary with an older migration set refuses a newer database. Downgrade therefore requires restoring the pre-upgrade backup.

## 5. Breaking-change assessment

- No configuration variable, database schema or command is removed by the v1.0.0 preparation.
- Sensor presentation includes the already-unreleased registry-hardening change: raw `on` is no longer rendered as a green success state; supported sensors show registry-owned meaning and unsupported sensors remain neutral.
- The stable release declares the existing single-guild and Discord-only scope. It does not promise compatibility for internal Go packages, which are not a public library API.

## 6. Security and reliability findings

Evidence in code and tests confirms:

- Guild and user allowlists are checked before commands run; DMs, other guilds and strangers are rejected.
- Every administrator mutation rechecks `auth.LevelAdmin` server-side.
- Entity reads and controls recheck current permissions; an unshared entity is indistinguishable from an unknown one.
- Control is deny-by-default and hard-limited to `light` and `switch` even if a database row says otherwise.
- Wizard confirmation and denial-audit interactions are replay-safe; denial memory and rate limiters are bounded.
- Configuration secrets redact every formatting/logging path; Home Assistant URLs reject embedded credentials.
- Notification messages disable Discord mentions, recheck access before delivery, and use bounded retry, rate and shutdown behavior.
- Migrations are embedded, checksummed and transactional; rollback and newer-schema refusal have tests.
- WebSocket handshakes, subscriptions, snapshots, pings and reconnects are bounded and cancellation-aware.
- Graceful shutdown cancels producers, drains notification work for a bounded period and closes the database.

No reachable Go vulnerability was found. `govulncheck` reports GO-2026-5932 in the required `golang.org/x/crypto` module because its `openpgp` package is unmaintained, but NeptHass does not import that package and no fix version exists. Gitleaks found no secret in 95 commits. No new production code is part of this scope cleanup.

## 8. Known limitations and release blockers

Release blockers:

1. Verify current `origin/main`, PR #12 and CI through an authenticated GitHub session.
2. Run the real Home Assistant integration suite in an isolated, onboarded environment.
3. Run the mandatory Discord smoke checks against a dedicated test guild.
4. Decide and publish a private security-reporting channel before public launch.
5. Obtain an independent security review or explicitly record its deferral and risk acceptance.
6. Decide the distribution channel and whether a signed/pinned container image will be published.

Known product limitations:

- Notifications are best-effort, in-memory and not suitable as a life-safety alarm.
- A condition that appears and clears entirely during a Home Assistant outage cannot be reconstructed.
- One Discord guild and one NeptHass instance are supported.
- Pending notifications can be lost on crash/restart and can occasionally duplicate.
- Dynamic sensor types and smoke/gas/carbon-monoxide behavior are intentionally outside v1.0.0.

## 9. Draft release notes

The release-candidate-specific draft, upgrade and rollback instructions are in [v1.0.0-rc.1.md](v1.0.0-rc.1.md).

### NeptHass v1.0.0

NeptHass v1.0.0 is the first stable release of the self-hosted Discord-first bridge for Home Assistant. Administrators explicitly choose which entities are visible, which lights and switches may be controlled, and which supported sensors may produce Discord notifications.

Highlights:

- Interactive entity discovery, sharing, aliases and synchronization.
- Real-time Home Assistant monitoring with reconnect and reconciliation behavior.
- Authorized device status and light/switch control through Discord.
- Notification rules with durations, hysteresis, unit-safe numeric thresholds and conservative start-up handling.
- Deny-by-default authorization, audit logging, replay protection, rate limiting and secret redaction.
- Transactional SQLite migrations and a non-root distroless container image.
- Neutral sensor rendering: an `on` value is never automatically presented as healthy.

Upgrade from v0.5.0 requires no new setting or database migration. Back up the data volume before every upgrade. Notifications remain best-effort and must not be used as a life-safety system.
